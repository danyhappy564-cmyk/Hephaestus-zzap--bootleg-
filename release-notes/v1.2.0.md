내가 저장해 둔 **무기 프리셋**을 부품까지 그대로 파는 상인 "Hephaestus"(한국어 게임에선 "헤파이스토스")를 추가합니다.
가격은 프리셋 부품들의 플리마켓 시세 합에서 할인(기본 90%, 유로)한 값입니다.

**<변경점>**

**1. SPT 4.1에서 동작하도록 새로 만듦 (C# 서버 모드)**
- 원작은 SPT 3.7(TypeScript) 모드라 4.1 서버에서는 아예 로드되지 않았습니다.
- 4.1 서버 모드(C#, `Hephaestus.dll`)로 옮겼습니다. 설치 위치는 `SPT_Runtime/user/mods/Hephaestus/`입니다.
- 4.1에서 쓸 수 없는 상인 ID(`hephaestus_alxk`)는 24자리 ID(`a18160fc82b4f2be55205c89`)로 바꿨습니다. 다른 모드와 겹치기 쉬운 초상화 경로(`img`)도 고유 경로로 바꿨습니다. 4.1 상인에게 필요한 항목(`isAvailableInPVE` 등)도 추가했습니다.
- 지원 범위는 SPT 4.1.5 이상 4.2 미만입니다. 처음엔 `~4.1.6`으로 묶었는데, 서버가 자기 버전을 4.1.5로 알리면 SPT가 **모든 모드를 로드하지 않는**(`NO MODS WILL BE LOADED`) 것을 실서버에서 발견해 범위를 넓혔습니다.
- 확인: 실제 SPT 4.1 서버에서 로드, 상인 목록 등록, 초상화 전송 확인. 게임 화면은 미검증입니다.

**2. 상인 목록을 만들면 내 프로필의 프리셋이 바뀌던 문제 수정 (원본 버그)**
- 원본은 상인 물건을 만들 때 프로필에 저장된 프리셋을 그대로 고쳐 썼습니다. 그래서 프리셋 첫 부품의 위치 정보 등이 상인용 값으로 바뀐 채 저장될 수 있었습니다.
- 이제 복사본으로만 작업해서 프로필의 프리셋은 손대지 않습니다.
- 확인: 실서버에서 상인 목록을 만든 뒤에도 저장된 프리셋이 그대로인 것을 확인했습니다.

**3. 여러 프로필(Fika 등)에서 남의 프리셋이 팔리던 문제 수정 (원본 버그)**
- 원본은 상인 물건이 서버 전체에 하나뿐이었습니다. 그래서 마지막에 접속한 사람의 프리셋으로 모두의 상인 물건이 통째로 바뀌었습니다.
- 이제 사람마다 자기 프리셋만 보이고, 자기 프리셋만 살 수 있습니다.
- 확인: 실서버에서 계정 두 개로 확인했습니다(B에게 A의 프리셋이 보이지 않음). Fika 환경에서는 미검증입니다.

**4. 가격이 계속 흔들리고 서버가 쓸데없이 일하던 문제 수정 (원본 동작)**
- 원본은 가방 정리나 아이템 이동처럼 무엇을 하든 상인 목록을 다시 만들었고, 그때마다 가격이 무작위로 달라졌습니다.
- 이제 상인 화면을 열 때와 살 때만 목록을 만듭니다. 가격은 무작위 없이 시세 합으로 고정돼 다시 열어도 같습니다.
- 확인: 실서버에서 다시 열어도 같은 가격·같은 ID인 것을 확인했습니다.

**5. 지운 모드의 부품이 든 프리셋 때문에 상인 화면이 깨질 수 있던 문제 수정**
- 프리셋에 지금 서버에 없는 아이템이 있으면 그 프리셋만 건너뜁니다. 디버그 로그를 켜면 몇 개 건너뛰었는지 나옵니다.
- 확인: 단위 테스트로 확인했습니다. 실서버·게임에서는 미검증입니다.

**6. 가격이 소수점이나 0으로 나오던 경우 수정**
- 가격은 항상 정수이고, 최소 1입니다. 시세를 하나도 못 구한 프리셋은 대체 가격(`cost`, 기본 123)에 할인을 적용합니다.
- 확인: 실서버에서 정수 가격(102유로 / 루블로 바꾸면 13,667루블)을 확인했습니다. 구매 시 표시 가격만큼 정확히 빠지는 것도 확인했습니다.

**7. 한국어/영어 자동 표시 (새 기능)**
- 상인 이름·설명·위치는 게임 언어가 한국어면 "헤파이스토스"와 한국어 설명으로, 그 밖의 언어면 원래 영어 문구로 나옵니다.
- 서버 로그는 서버 PC의 윈도우 언어를 따릅니다. 한국어면 `[Hephaestus] 상인 추가 완료 (화폐 EUR, 할인 90%)`처럼 나옵니다.
- 확인: 실서버에서 `kr`/`en`/`ru` 문구와 한국어 서버 로그를 확인했습니다. 게임 화면 표시는 미검증입니다.

**<Changes (English)>**

Adds a trader, "Hephaestus", that sells **your own saved weapon presets** with every part attached. The price is the flea-market value of the parts minus a discount (90% by default, in euros).

**1. Rebuilt for SPT 4.1 (C# server mod)**
- The original is an SPT 3.7 TypeScript mod and does not load on 4.1 at all.
- Now a 4.1 C# server mod (`Hephaestus.dll`) in `SPT_Runtime/user/mods/Hephaestus/`.
- The trader ID `hephaestus_alxk` is not a valid 4.1 ID, so it is now `a18160fc82b4f2be55205c89`. The portrait path is now unique; the old `img` path could clash with other mods. Fields that 4.1 traders need, such as `isAvailableInPVE`, were added.
- Supports SPT 4.1.5 up to (not including) 4.2. A first version required `~4.1.6`. On a real server that reports 4.1.5, SPT then loads **no mods at all** (`NO MODS WILL BE LOADED`), so the range was widened.
- Status: load, trader registration and portrait checked on a real SPT 4.1 server. Not yet checked on the game screen.

**2. Fixed: building the trader stock changed your saved preset (original bug)**
- The original edited the preset stored in your profile while building the offer, so the first part's location data could be saved with trader values.
- It now works on a copy only.
- Status: checked on a real server.

**3. Fixed: with several profiles (Fika etc.) everyone got the last player's presets (original bug)**
- The original had one stock for the whole server, rebuilt from whoever logged in last.
- Each player now sees and can buy only their own presets.
- Status: checked on a real server with two accounts. Not tested with Fika.

**4. Fixed: prices kept jumping and the server rebuilt the stock all the time (original behaviour)**
- The original rebuilt the stock on almost every inventory action, with a random price each time.
- The stock is now built only when you open the trader or buy. The price is the plain market sum with no randomness, so it stays the same when you reopen.
- Status: checked on a real server.

**5. Fixed: presets with items from a removed mod could break the trader screen**
- Such presets are skipped. Debug logging prints how many were skipped.
- Status: unit tests only.

**6. Fixed: decimal or zero prices**
- Prices are whole numbers, minimum 1. Presets with no market data use the fallback price (`cost`, default 123) with the discount applied.
- Status: checked on a real server (102 EUR, or 13,667 RUB after switching currency). Buying takes exactly the shown price.

**7. Korean/English automatically (new)**
- Trader name, description and location are shown in Korean ("헤파이스토스") when the game language is Korean, otherwise in the original English.
- Server log messages follow the server PC's Windows language.
- Status: `kr`/`en`/`ru` texts and the Korean server log checked on a real server. Not yet checked on the game screen.

**8. F12 settings (new, optional `HephaestusClient.dll`)**
- Change the discount, price currency (EUR/RUB/USD), fallback price and server debug log from F12.
- Changes are saved straight to the server's `config.json` (the `HELP_` lines are kept). No server restart is needed; **reopen the trader** to see the new price.
- The F12 language follows the game when set to "Auto", and uses the Windows display language before the game has picked one. Korean or English can be forced.
- The plugin finds the game's language at runtime instead of referencing game files, so a game update cannot break loading.
- Status: the server side was checked on a real server. **The F12 screen itself has not been checked in game yet.**

**9. Other**
- Added `Hephaestus.sln` with the server, client and test projects.
- Added unit tests (`tests/Hephaestus.Tests`, 94 checks) and a real-server test script (`tests/e2e/e2e.py`, 32 checks).
- Build: `dotnet build Hephaestus.sln -c Release`, 0 errors, 0 warnings.
- The `user/` folder is the original 3.7 mod, kept for reference only. Do not install it.

**Known issues**
- The game screen and the F12 screen have not been checked in game yet.
- The `HephaestusClient.dll` in the zip was compiled against a stand-in for Unity; the resulting DLL only references BepInEx and netstandard. If it misbehaves, build it yourself with `dotnet build Hephaestus.sln -c Release`.
- If F12 causes trouble, delete only `BepInEx/plugins/HephaestusClient.dll`. The trader works with the server mod alone, and `config.json` can be edited by hand.

**Install / update**
- Extract `Hephaestus-1.2.0.zip` into your SPT folder. It adds `SPT_Runtime\user\mods\Hephaestus\` and `BepInEx\plugins\HephaestusClient.dll`.
- Delete any old 3.7 folder (`user/mods/Hephaestus` with `src/mod.js`).
- The server log shows `[Hephaestus] trader added` when it loads. Save a preset in the weapon modding screen, then open the trader.

Hi everyone,

I'd like to share a few thoughts and important warnings regarding the process of porting mods from version 4.0 to 4.1.

Following the recent "ECOT" mod incident, I've had a lot of time to reflect on my actions.
I’m not here to lecture anyone—I’m writing this simply in the hope that you’ll keep these points in mind.


**1. I am not a professional programmer; I am mostly a "vibe coder" who relies heavily on AI.**

By that, I mean I’m not someone who spends days designing and painstakingly crafting mods by hand from scratch.
At the same time, having tinkered with simple mod edits back in the TS/JS (SPT 2.3.1) days, I know firsthand how much time, effort, and care goes into this process.
Therefore, even if a mod is covered under an MIT License, if the original author requests that I delete the source code and stop distribution, I will willingly comply.


**2. Please DO NOT re-distribute or re-upload these modified mods to 3rd/4th party places.**

Even if my ported version has some fixes or improvements, please do not treat it as a long-term solution. Unlike official releases on "THE FORGE," I do not perform thorough debugging or full security scans.
Furthermore, imagine how disruptive it would be if someone mistook my ported build for an "official release" and pestered the original author about bugs in my version. It would be terrible.
Moving forward, I intend to approach any porting work with the utmost respect for original modders.
If I had spent days pouring my heart into making a mod, only to have someone take my code and modify it however they pleased, I wouldn't feel good about it either.
Therefore, when writing README.md files on GitHub, I will always credit the original creators, and if it's not a mod I built from scratch, I will fully respect the original modder's decisions and opinions.


**3. Please respect the original creators.**

If people ignore warning 2. and act as if my port is the "real deal," I would feel immense guilt.
Please do not do that. As the saying goes, "When in Rome, do as the Romans do"—and showing proper respect and courtesy is essential.
Instead, please visit the original creators' comment sections on The Forge to leave warm words of appreciation, encouragement, or even buy them a coffee/leave a tip if you can


**Thank you for reading this long post.**
**Stay safe and stay happy!**
